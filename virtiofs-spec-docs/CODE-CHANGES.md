# virtio-fs spec: changes to OpenVMM's code

Every change that the virtio-fs spec work makes to what a normal build
compiles (code, types, dependencies, build settings), numbered ("code
change N"). Annotations under `cfg_attr(verus_keep_ghost, ...)` and code
under `cfg(verus_keep_ghost)` are not listed: a normal build does not see
them. The base is Pedro Henrique Penna's `feature/microvm/dev` at
`db42fde04`.

| # | Where | Change | Why |
|---|---|---|---|
| 1 | `Cargo.toml` (workspace) | `[patch.crates-io]` points `verus_builtin_macros` and `vstd` to the patched copies in `verus-patches/`, which are excluded from the workspace | the patches the spec needs (`verus-patches/README.md`) |
| 2 | `Cargo.toml` (workspace) | the workspace dependency `vstd` (`=0.0.0-2026-10-04-0306`, feature `std`) | the first crate that uses Verus, `virtiofs` (change 3) |
| 3 | `vm/devices/virtio/virtiofs/Cargo.toml` | depends on `vstd`; `[package.metadata.verus] verify = true` | the access policy's spec (`microvm/policy.spec.rs`). A normal build now compiles `vstd` as well |
| 4 | `Cargo.toml` (workspace) | `cfg(verus_keep_ghost)` added to the `unexpected_cfgs` lint's `check-cfg` list | the condition under which the spec is compiled; without it, every annotation gives a warning in a normal build |
| 5 | `verus-patches/vstd/std_specs/` | new `path.rs` (patch `vstd-0003`): `Path` and `PathBuf` declared to Verus, with their view (the path's components) | Rust's orphan rule forbids implementing `vstd`'s `View` for `std`'s types in `virtiofs`; only the patched `vstd` is affected |
| 6 | `verus-patches/vstd/std_specs/` | `convert.rs` and `path.rs` (patch `vstd-0004`): a spec of `AsRef::as_ref`, for `&T`, `Path` and `PathBuf` | `lxutil`'s methods take `impl AsRef<Path>`, and their contracts must name the path they are given; only the patched `vstd` is affected |
| 7 | `vm/devices/support/fs/lx/Cargo.toml` | depends on `vstd`; `[package.metadata.verus] verify = true` | the view of `LxStr` (`src/string.spec.rs`), the bytes of a name in the FUSE operations' contracts. A normal build of `lx` now compiles `vstd` as well |
| 8 | `vm/devices/support/fs/lx/src/string.rs` | `LxStr` declared to Verus (`cfg_attr(verus_keep_ghost, ...)` only), and a `mod spec` under `cfg(verus_keep_ghost)` | the same; a normal build does not see either |
| 9 | `vm/devices/support/fs/fuse/Cargo.toml` | depends on `vstd`; `[package.metadata.verus] verify = true` | the `Fuse` trait's contracts. A normal build of `fuse` now compiles `vstd` as well |
| 10 | `vm/devices/support/fs/fuse/src/lib.rs` | `pub trait Fuse` becomes `pub trait Fuse<G: FuseGhost>: Send + Sync + FuseOwns<G> where G::V: FuseState` (the three are spec-only traits, empty in a normal build); a `pub mod spec` (`lib.spec.rs`, `FuseState`) included in every build | the ghost state passed to each operation, as the trait's type parameter (`CODE-OVERVIEW.md`, "Why a type parameter, and what it costs"); `Send + Sync` moves from `Session`'s field to the trait, since Verus refuses `dyn Fuse + Send + Sync` |
| 11 | `vm/devices/support/fs/fuse/src/session.rs`, `session/saved_state.rs`, `conn.rs`, `tests/fuse_hello.rs` | `Session` becomes `Session<G>` (field `Box<dyn Fuse<G>>`); `Connection::run` takes `Fuse<G>`; the crate's test file systems implement `Fuse<()>` | the same; `()` is the ghost state of a file system with none (`impl FuseState for ()`, which permits nothing) |
| 12 | `vm/devices/virtio/virtiofs/src/lib.rs`, `section.rs`, `virtio.rs`, `microvm/owner.rs`, `microvm/device.rs`, `microvm/fs.rs`, `microvm/owner_tests.rs` | `impl Fuse for ...` becomes `impl Fuse<spec::VirtioFsGhost> for ...` (`VirtioFs`, `SectionFs`, `DormantMicrovmFs`); `fuse::Session` becomes `fuse::Session<spec::VirtioFsGhost>`; a `pub mod spec` (`lib.spec.rs`) included in every build | the same; the ghost state's types must exist in a normal build. Nothing changes at runtime |
| 13 | `vm/devices/virtio/virtiofs/src/microvm/policy.rs` | the `spec` module (`policy.spec.rs`) included in every build (its `proof` module still under `cfg(verus_keep_ghost)`) | `SubtreePolicyView` is a field of the ghost state (an inode's view), which a normal build compiles |
| 14 | `verus-patches/vstd/vstd.rs` (patch `vstd-0005`) | in a normal build, `std_specs::path::PathView` (the alias alone) | the ghost state's types name it, in a normal build too; only the patched `vstd` is affected |
| 15 | `vm/devices/virtio/virtiofs/src/lib.rs` (and three test call sites) | **a fix, not for Verus**: `get_file` takes the request's node id, and refuses a handle unless the guest still holds that node and the handle is that node's | `BUGS.md`, bug 1: a handle kept working after the guest gave its node back, with stale names; patch `patches/0001-virtiofs-a-handle-only-with-its-node.patch` |
| 16 | `vm/devices/virtio/virtiofs/src/lib.rs` (`rename`) | **a fix, not for Verus**: a rename of a name onto itself returns after the permission checks | `BUGS.md`, bug 2: it dropped every name at or below it from the nodes; patch `patches/0002-virtiofs-rename-onto-itself-keeps-names.patch` |
| 17 | `vm/devices/virtio/virtiofs/src/lib.rs` (`create`, `check_create_existing`, `InodeMap::find`) | **a fix, not for Verus**: a create that may write or truncate an existing file applies `open`'s rule to it | `BUGS.md`, bug 3: it could truncate a file whose other name is not writable; patch `patches/0003-virtiofs-create-on-existing-file-follows-open.patch` |
| 18 | `vm/devices/virtio/virtiofs/src/inode.rs` (and `inode.spec.rs`, included in every build) | each inode's `path` lock: `parking_lot::RwLock<PathBuf>` becomes vstd's `RwLock<InodePath, PathRule>`, where `InodePath` is the path plus its ghost piece (a `Tracked`, empty at runtime) and `PathRule` the lock's rule (a ghost value, empty at runtime); its four writers use `acquire_write` / `release_write`; `get_path()` returns a copy of the path (`PathBuf`) instead of a read guard, so the two callers that cloned it (`clone_path`, the inode's `DedupKey`) no longer do | `CODE-OVERVIEW.md`, "Lock invariants the spec needs": Verus knows what a lock holds only through its rule. At runtime: the lock spins instead of sleeping (never contended in the microVM), and each `get_path()` copies the path (one allocation): 14 of its 16 callers only borrowed it under the read guard before (an `lstat`, `open`, ... on the host), and now get a copy; a borrow cannot outlive vstd's read handle, which must be released explicitly (avoidable, if it matters, with a `with_path(|p| ...)` that lends the path to a closure under the read handle). `with_attr` creates the piece and the rule with `assume_new()` (marked PLACEHOLDER): their real creation is the proof's job |
| 19 | `vm/devices/virtio/virtiofs/src/inode.rs`, `microvm/inode.rs` (`from_saved`) | each inode's `aliases` lock: `parking_lot::RwLock<BTreeSet<PathBuf>>` becomes vstd's `RwLock<InodeAliases, AliasesRule>` (the names plus their ghost piece, and the lock's rule; both ghost, empty at runtime); its users (`lookup`, `aliases`, `add_alias`, `remove_alias_prefix`, `rename_alias_prefix`, `exchange_alias_prefixes`, `from_saved`) use `acquire_*` / `release_*`; `inode.rs` no longer imports `parking_lot::RwLock` | as change 18. At runtime: the lock spins instead of sleeping; each lock is released explicitly at the end of the section that used to drop its guard (in `remove_alias_prefix`, after the path lock, as before); no extra copies. `with_attr` creates the piece and the rule with `assume_new()` (PLACEHOLDER) |
| 20 | `vm/devices/virtio/virtiofs/src/lib.rs`, `microvm/fs.rs` (and the tests: `lib.rs`, `inode.rs`, `microvm/fs_tests.rs`, `microvm/symlink_tests.rs`) | the inode table's and the file table's locks (`VirtioFsInner::inodes`, `files`): `parking_lot::RwLock<InodeMap>` and `RwLock<HandleMap<Arc<VirtioFsFile>>>` become vstd's `RwLock<InodeTableLocked, InodeTableRule>` and `RwLock<FileTableLocked, FileTableRule>` (each table plus its ghost half, empty at runtime), made by `InodeTableLocked::new_lock` / `FileTableLocked::new_lock`. Every use is an explicit `acquire_*` ... `release_*`; where a section returned early while holding the guard (`?`, `anyhow::ensure!`), it now computes its result, releases the lock, then returns it (`get_file`, `reserve_inode`, `reserve_file`, `InodeReservation::insert`, `FileReservation::insert`; `save_microvm_state`'s two table walks run in an immediately called closure). Tests reach the tables through two test-only helpers, `VirtioFsInner::with_inodes` / `with_files` | `CODE-OVERVIEW.md`, "Who writes what in the locks' rules": the rules tie `g`'s halves to the real tables, and `owns` (now real) ties `g` to this file system's locks. At runtime: the locks spin instead of sleeping; no extra copies. As for changes 18 and 19: a panic while a lock is held leaves it held (a `parking_lot` guard was released as the panic unwound), so later requests would spin; `new_lock` creates the ghost half and the rule with `assume_new()` (PLACEHOLDER) |
| 21 | `vm/devices/virtio/virtiofs/src/file.rs` | `VirtioFsFile::open_flags` is `pub(crate)` (was private) | the file table's rule reads it (whether the handle was opened for writing); no change at runtime |
