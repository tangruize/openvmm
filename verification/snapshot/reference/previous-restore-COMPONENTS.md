## Coverage interpretation

The model's serialized core inventory requirement covers the fixed microVM entries (`pic`, `ioapic`, `pit`, `rtc`, `microvm-portb`, `microvm-shutdown`, and `microvm-snapshot-request`). Partition, VP/LAPIC, VM-time, RAM, and backend-clock state are modeled in dedicated fields rather than duplicated as generic components. Runtime-only `chipset`, `input`, and conditional `lines/*` units are a separate inventory because they intentionally produce no blob. Dynamic virtio units use stable manifest identities. VMBus and VTL2 VMBus are supported conditionally by the worker but are not enabled by the core microVM profile.

The production partition schema stores backend VP state as opaque blobs. `saved_cpu_state_fields` records the decoded source projection and `destination_cpu_state_fields` supplies compatibility; `architectural_state` and `optional_architectural_state` require exact preservation only for source-present fields. Destination-only fields remain initialized and outside this restore projection. This avoids inventing a backend-neutral register schema and does not hide the implementation-visible TSC/LAPIC mutations, which are modeled separately and exactly.

The remaining proof gap is implementation correspondence, not an undefined restore relation: codecs and manifest validation must establish `valid_snapshot`; partition decoding must authenticate ReferenceTime; prepared memory, runtime-unit inventory, capabilities, and attachments must establish `prepared_inputs_valid`; provider bridges must authenticate clock sample provenance and ordering; state-unit, device, and hypervisor operations must establish the component functions; concrete observers must implement `vm_view`; and async control flow must establish the execution/publication flags. Multi-VP adjustment is not atomic, so the error contract intentionally permits unpublished partial state and requires caller cleanup.
