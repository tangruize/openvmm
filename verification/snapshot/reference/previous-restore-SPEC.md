# Snapshot restore contract

## Target boundary

This contract describes the successful snapshot branch of `InitializedVm::load` in `openvmm/openvmm_core/src/worker/dispatch.rs`. Its boundary is the returned `LoadedVm` after state restoration, downtime compensation, and acquisition of the temporary VP stop guard, but before any guest instruction can execute. Snapshot parsing, file connection, memory-backing construction, private virtio-device application, queue activation, guest repair, VP release, and external-ready publication are separate protocol boundaries.

The contract applies to supported microVM ABI-v1/v2 snapshots. `SnapshotArtifacts` is the decoded file/manifest view. `PreparedInputs` adds resources that the caller constructs from that view. `VmResources` is an independent logical observation of the created VM; it does not cache or return the snapshot argument. `snapshot_view`, `vm_view`, and `represents` therefore remain independent abstractions.

## Logical state and preparation

Together, `SnapshotState`, `PreparedInputs`, and `VMState` include machine and destination-backend identity, RAM as GPA-to-byte content, partition state, a stable ordered vCPU prefix, capability-indexed optional vCPU fields, LAPIC state, serialized state-unit/device identity and content, runtime-only unit identity, VM time, backend time, and external resource identities. The destination backend is an environment choice rather than a serialized snapshot field. Likewise, `saved_guest_online_vps` is an explicit logical interpretation of saved guest state, not a claimed file field; the guest's actual representation remains in the preserved CPU/RAM/device state. Host virtual addresses, file descriptors, task identities, and handles are deliberately hidden because they may change without changing the restored VM.

The caller must provide a decoded snapshot whose machine contract, serialized component inventory, vCPU count, stable IDs, source capability field domain, and serialized virtio common state are valid. The independently constructed destination inventory must exactly match the saved inventory. Destination virtio feature banks, queue count, and queue capacities are separate `VirtioDestinationContract` inputs rather than invented snapshot fields. Runtime-only `chipset`, `input`, and conditional `lines/*` units are represented separately because their `save` operation returns no blob; their stable IDs are unique, the always-created chipset and input units occur exactly once, and the selected runtime inventory is preserved in the result view. The RAM file must contain exactly the packed bytes named by the manifest ranges. The prepared backing must expose those bytes at the corresponding GPAs, including the supported split layout with low RAM below 3 GiB, a 3–4 GiB hole, and high RAM beginning at 4 GiB with packed file offsets. Snapshot artifacts must remain immutable, and state units and VPs must still be stopped.

External attachments use a typed reconnect policy. Bound resources require exact topology, read-only status, and content identity. An ABI-v2 PLATFORM read-only layer may carry normalized `unbound` saved identity and select new destination content while preserving topology; this exception does not apply to writable, non-platform, or exact-content resources. The selected destination identity remains visible in the VM view.

An ABI-v2 activation request must be one of 1, 2, 4, or 8, be at least the boot-online count, and not exceed snapshot capacity. MSHV may instantiate that requested prefix. KVM and WHP instantiate full capacity while retaining the request as unapplied guest-repair metadata. The saved guest-online observation is preserved at this boundary; the host request does not claim that guest activation has occurred.

## Successful result

`pre_execution_target` is a function of only the snapshot, prepared external inputs, and explicit restore parameters. A successful restore must satisfy `Represents(resources, pre_execution_target(inputs, params))`.

RAM bytes, partition state, stable component identities, immediate opaque state-unit payloads, VMBus connected/disconnected state, channels, GPADLs and pending messages, source-present vCPU architectural fields, and non-LAPIC interrupt state are preserved exactly. The instantiated vCPU sequence is the selected stable prefix. Destination-only optional CPU fields are outside the restored projection and remain initialized by the destination backend; source-present fields must be supported by the destination. TSC-deadline presence is bound to source capability and may only be restored when the destination supports it; MSHV explicitly rejects such a source field. Core microVM inventory requires PIC, IOAPIC, PIT, RTC, port-B, shutdown, and snapshot-request units; shutdown and snapshot-request each carry a present unit `NoSavedState` blob, not an absent blob. Partition, vCPU/LAPIC, and VM-time state have dedicated fields.

Virtio common state is restored immediately: configuration, status, feature banks/selectors, config generation, queue format/size/addresses/progress, and component identity are unchanged. All queues, including disabled queues, must fit the separately supplied destination capacity; saved feature banks must have the supported count and be a subset of destination features; queue count must match. Enabled queues additionally require a nonzero size, split-ring power-of-two size, checked full descriptor/available/used spans in RAM, required alignment, and non-overlap within and across queues. An enabled queue under DRIVER_OK must contain serialized progress. Private state remains `Pending(saved_payload)` at load return, including `Pending(None)`; queues are not started, and pending-kick flags are freshly created as false rather than read from snapshot data. Device-private application and any endpoint-generation change occur later.

Clock state is split into values explicitly programmed by restore and live observations at named sample points. `ClockEnvironment` is fixed before the expected result and records authenticated provider samples; it is never chosen from returned observations. A future production bridge must prove sample provenance and call ordering. System time may jump forward or backward, and MSHV does not freeze virtual TSC, so raw return-time reads are not required to equal saved or programmed values.

When restore-time metadata is present, x86 TSC advancement starts from the actual pre-adjust read and uses checked `u128` nanoseconds-times-frequency multiplication, division by 1,000,000,000, checked `u64` conversion, and checked addition; aarch64 has no TSC adjustment in this path. The raw return TSC remains a separate authenticated sample. LAPIC elapsed ticks use the saved or destination APIC frequency and the production DCR-code mapping `0xb→0, 0→1, 1→2, 2→3, 3→4, 8→5, 9→6, 0xa→7`, where the result is the power-of-two divisor shift. A non-expired timer subtracts elapsed ticks; an expired one-shot clears CCR; an expired periodic timer reloads `ICR - ((elapsed - CCR) % ICR)`. Interrupt delivery sets IRR and clears TMR and auto-EOI for an unmasked vector of at least 16. The separately accessed, capability-dependent TSC deadline uses the production wrapping signed-distance test, queues an expired deadline, and clears it. Absence means no source deadline field is restored, not that a destination-only register was observed as absent.

VM time advances by truncated 100 ns ticks with `u64` wrapping. RTC preserves the lossless `Option<u16>` transaction mask: `None` and `Some(0)` remain distinct. Serialized `time_valid: None` separately normalizes to `true`, and microVM-v1 oscillator/binary/24-hour controls plus coherent-calendar conditions are preconditions. RTC restore programs saved time at one host sample; its downtime hook reads the live provider at a later sample, adds truncated milliseconds with checked `i64` arithmetic, and reprograms it at another sample. The return observation incorporates the final host sample, including legitimate forward or backward jumps even without metadata.

KVM reference time is decoded from the partition blob as `ceil(clock_ns / 100)` and initially programmed with saturating multiplication by 100. Its downtime hook reads the then-current KVM clock, performs checked nanosecond addition, and writes the result; return readback may advance afterward. MSHV and WHP use the no-op backend hook, but their live clocks are not thereby asserted frozen. Arithmetic overflow makes successful restoration unavailable.

At return, the activation request is unapplied, VPs remain stopped, and external-ready has not been published. Later `resume()` ordering, guest repair, private-device application, queue start, and readiness publication are intentionally not part of this equality boundary.

## Error boundary and proof status

The error contract guarantees no guest execution and no external-ready publication. It does not promise transactional rollback: state-unit restore and multi-vCPU downtime adjustment may have partially modified resources before another component fails. Those unpublished resources remain caller-owned and require cleanup/drop.

The Verus model defines the abstract success relation for this boundary and checks representative positive and rejection cases. Local transformations are deterministic from declared inputs; live-clock behavior is parameterized by named, authenticated samples with exact provider equations. It does not prove that the dependency-heavy async body of `InitializedVm::load`, snapshot/partition codecs, provider sample provenance, hypervisor calls, state-unit orchestration, device implementations, or concrete resource observers establish that relation. The only implementation body directly shared with and proved by Verus is `restore_vp_plan`; source-text anchors are drift alarms, not semantic or control-flow proofs.
